## الأهداف

الهدف من هذا المشروع هو استكشاف إطار العمل **Struts 1.x**، الذي نشأ من مشروع Jakarta Struts التابع لمؤسسة **Apache Software Foundation**.

يوفر Struts إطار عمل قياسي لتطوير تطبيقات الويب Java القائمة على نموذج الهندسة **MVC (Model–View–Controller)**.

الأهداف التعليمية هي:

* فهم مبادئ نموذج MVC
* هيكلة تطبيق ويب Java بشكل صحيح
* الفصل بوضوح بين العرض والمنطق التطبيقي والوصول إلى البيانات
* تنفيذ هذه البنية باستخدام Servlet و JSP
---
## نموذج MVC
يهدف نموذج **MVC (Model–View–Controller)** إلى الفصل بين:
| المستوى             | الدور                  |
| ------------------ | --------------------- |
| **View (V)**        | واجهة المستخدم |
| **Controller (C)** | منطق التطبيق   |
| **Model (M)**     | الوصول إلى البيانات     |

تُعرف هذه البنية أيضًا باسم **البنية ثلاثية المستويات**.

### 1️⃣ العرض – واجهة المستخدم

* عادةً ما يكون متصفح ويب
* يمكن أن يكون أيضًا تطبيقًا مستقلًا
* يرسل طلبات HTTP ويقوم بتنسيق النتائج

### 2️⃣ وحدة التحكم – منطق التطبيق

* تعالج طلبات المستخدمين
* تنسق أنشطة المعالجة
* تستدعي فئات الأعمال ومصادر البيانات

### 3️⃣ النموذج – مصادر البيانات

يمكن أن تتكون من:
*
* قاعدة البيانات
* ملفات مسطحة
* خدمات الويب
* دليل LDAP
* أي مصدر دائم آخر
*
* الهدف الرئيسي لنموذج MVC هو الحفاظ على **استقلالية قوية** بين هذه المستويات الثلاثة من أجل الحد من تأثير التغييرات.

## MVC مع Servlet و JSP

عند تطبيق MVC مع تقنيات Java EE التقليدية (Servlet + JSP)، يتم تنظيم البنية على النحو التالي:

### 🔹 وحدة التحكم
* يعمل **Servlet** كنقطة دخول للتطبيق
* يركز طلبات HTTP

### 🔹 منطق الأعمال
* مجموعة من **فئات الأعمال**
* تنفذ القواعد الوظيفية

### 🔹 الوصول إلى البيانات

* **فئات الوصول إلى البيانات (DAO)**
* تتفاعل مع قواعد البيانات أو الأنظمة الأخرى

### 🔹 طرق العرض

* صفحات **JSP**
* مسؤولة عن العرض

## لماذا Struts؟

تقوم Struts بتنظيم هذا الهيكل:

* من خلال مركزية التحكم في الطلبات
* توحيد إدارة الإجراءات
* تسهيل فصل المهام
* تنظيم تطبيقات الويب Java بطريقة صناعية

وبالتالي، يوفر إطار عمل قوي لتطوير تطبيقات الويب التي تلتزم بدقة بهندسة MVC.
